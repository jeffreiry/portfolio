## Job description original

> **Product Design Systems Designer (Remote, Belém)**
>
> Blacksmith Agency builds websites and marketing programs for clients across the US. As Product Design Systems Designer at Blacksmith, you own how our client design systems get built. You take a brand and a few reference sites, then extract the pattern into a working system: tokens, variables, modes, and core components a build pipeline can execute without asking you questions. Precision is the job.
>
> This is a senior, systems-first seat. Not one-off pages, not maintenance. You stand up new systems fast and get them right the first time, across several client brands at once.
>
> **What You Will Own**
> Build token architecture in Figma using variables, modes, and semantic naming our pipeline can read predictably.
> Ship core component libraries that hold up across an entire site, not just a homepage.
> Document the system so a developer or an automated pipeline can execute it without questions.
> Work across several client brands at once, each looking distinctly different, with the same structural rigor.
>
> **What You Bring**
> 4+ years designing for the web, with real design system work in your portfolio.
> Fluency in Figma variables, component properties, auto layout, and variants. Actual architecture, not just tidy files.
> A portfolio where the work looks different from client to client but the rigor underneath is the same.
> Strong English and overlap with US business hours.

## Gaps prioritários

### 🔴 Bloqueadores de candidatura

**Figma architecture técnica não evidenciada publicamente.** Este é o gap mais crítico porque a vaga foi escrita com linguagem deliberadamente técnica — "variables, modes, semantic naming our pipeline can read predictably" — o que indica que o revisor da Blacksmith vai procurar no portfolio evidência direta de token architecture, não só menção de Figma como ferramenta. O portfolio atual descreve Figma como ferramenta central mas não exibe um único artefato: nenhuma screenshot de estrutura de components, nenhum frame mostrando token hierarchy, nenhuma documentação de variable modes. Cartela Cores é o case mais próximo (tokens de cor com regras de decisão, alinhamento WCAG), mas o case não demonstra implementação em Figma variables nem nomenclatura semântica orientada a pipeline. Para mitigar: publicar um case técnico de design system com screenshots de estrutura de componentes em Figma (component properties, auto layout, variant matrix), mesmo que seja um projeto pessoal ou a Cartela Cores expandida com essa camada técnica explícita.

**Framing multi-cliente ausente.** A vaga define o papel como "work across several client brands at once, each looking distinctly different, with the same structural rigor" — o que é uma competência específica de agência/consultoria: extrair padrão de qualquer brand brief e converter em sistema executável. Jeferson tem sim variação de clientes (Hypera, Arezzo, Coca-Cola, clientes confidenciais), mas o portfolio não está narrado como evidência desse padrão. Cada case é uma história de produto isolada; não existe um case ou seção que mostre "dado este brand → extraí este token set → construí estes componentes → entregável que pipeline pode consumir". O recrutador da Blacksmith não vai fazer essa inferência: o portfolio precisa fazer esse argumento explicitamente. Mitigação possível: reescrever o framing de introdução do portfolio para tornar a lógica de sistemas transversal visível, mesmo sem adicionar novos cases.

### 🟡 Diferenciais ausentes

A JD não lista diferenciais formalmente, mas a leitura do "What You Will Own" implica competências que o portfolio atual não endereça:

1. **Documentação orientada a developer/pipeline.** A vaga menciona explicitamente "document the system so a developer or an automated pipeline can execute it without questions." Power Apps Dummy App documenta componentes para adoção por times, o que é a analogia mais próxima — mas o contexto é adoção interna em low-code Microsoft, não handoff para build pipeline web. Ação: em qualquer case futuro de design system, documentar explicitamente a estrutura de handoff, nomenclatura de tokens e o critério de "zero dúvidas para o dev".

2. **Web como plataforma primária (não produto SaaS).** Os cases enterprise de Jeferson são majoritariamente plataformas SaaS internas (Enterprise AI, Shipping Platform, HYPERGESTOR). Del Valle e Arezzo são web, mas narrados como redesigns de produto, não como sistemas web construídos com token architecture. A Blacksmith trabalha com "websites and marketing programs" — um contexto de web marketing/CMS/site, não SaaS. Essa distinção de contexto (componentes de site vs. componentes de app) é relevante e o portfolio não a endereça. Ação: se candidatar, alinhar a narrativa sobre Del Valle e Arezzo para enfatizar decisões de sistema web (tipografia responsiva, grid, componentes reutilizáveis de marketing) mesmo que os cases sejam sobre redesign de produto.
